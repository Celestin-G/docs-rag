# docs-rag

A local RAG (Retrieval-Augmented Generation) engine for the [Formance](https://formance.com) documentation. Ask questions about the platform in natural language — answers are generated by a local LLM using only the official docs as context. No external API keys, no data leaving your machine.

---

## How it works

```
Question → embed (nomic-embed-text) → pgvector similarity search → top chunks → qwen2.5:32b → streamed answer
```

1. **Ingest** — the Formance docs repo is walked, `.md`/`.mdx` files are parsed, MDX/JSX noise is stripped, and the text is split into ~500-token chunks by heading hierarchy (H2 → H3).
2. **Embed** — each chunk is embedded via Ollama (`nomic-embed-text`, 768 dims) and stored in PostgreSQL with a pgvector HNSW index.
3. **Search** — at query time, the question is embedded and the top-k most similar chunks are retrieved (cosine similarity, diversity filter: max 2 chunks per source file).
4. **Generate** — the retrieved chunks are injected into the system prompt of `qwen2.5:32b` via Ollama. The model answers strictly from the docs for technical facts, and may synthesise step-by-step guidance from documented concepts.
5. **Stream** — the answer is streamed token by token to the web UI via SSE.

## Setup

### 1. Clone this repo

```bash
git clone https://github.com/celestingeniaut/docs-rag
cd docs-rag
```

### 2. Clone the Formance docs

```bash
git clone https://github.com/formancehq/docs ~/formance-docs
```

You can put it anywhere — you will point `DOCS_PATH` at it.

### 3. Start PostgreSQL

```bash
docker compose up -d
```

This starts a `pgvector/pgvector:pg17` container on port 5432 with credentials `rag / rag / ragdb`.

### 4. Pull the Ollama models

```bash
# Embedding model (fast, ~270 MB)
ollama pull nomic-embed-text

# Generation model (slow to pull, ~20 GB — grab a coffee)
ollama pull qwen2.5:32b
```

Make sure Ollama is running (`ollama serve` or the desktop app).

### 5. Set environment variables

```bash
export DATABASE_URL="postgres://rag:rag@localhost:5432/ragdb"
export DOCS_PATH="$HOME/formance-docs"
```

Add these to your shell profile (`~/.zshrc`, `~/.bashrc`) to avoid repeating them.

## First run

Run the three commands in order — only needed once (or after a docs update):

```bash
# 1. Create the pgvector extension and the doc_chunks table
go run . migrate

# 2. Parse, embed and index all documentation (~5–15 min depending on hardware)
go run . ingest

# 3. Start the web UI
go run . serve
```

Then open **http://localhost:8080**.

---

## Daily use

```bash
go run . serve
```

That's it. The index persists in PostgreSQL — no need to re-ingest unless the docs change.

### Update the index after a docs pull

```bash
cd ~/formance-docs && git pull
cd ~/docs-rag
go run . migrate   # drops and recreates the table
go run . ingest    # re-embeds everything
```

## CLI reference

```
go run . migrate          Apply DB migrations (creates extension + table)
go run . ingest           Walk DOCS_PATH, embed chunks, store in pgvector
go run . ingest --clean   Truncate existing data before ingesting
go run . serve            Start the web UI (default: :8080)
go run . serve --addr :9090   Listen on a custom port
go run . ask "question"   Ask a question from the terminal (no UI)
```

## Project layout

```
cmd/
  migrate.go   DB schema setup
  ingest.go    Documentation ingestion pipeline
  serve.go     HTTP server entry point
  ask.go       Terminal Q&A mode
internal/
  chunker/     MDX stripping, heading-aware chunking, H2>H3 breadcrumbs
  embedder/    Ollama nomic-embed-text client
  llm/         Ollama qwen2.5:32b streaming client + system prompt
  server/      HTTP handlers, SSE streaming, embedded web UI
  store/       pgvector insert / cosine search
docker-compose.yml   PostgreSQL + pgvector
```

---

## Stack

- **Go** — single binary, no runtime dependencies
- **Ollama** — `nomic-embed-text` (embeddings) + `qwen2.5:32b` (generation)
- **PostgreSQL 17 + pgvector** — HNSW index, cosine similarity search
- **Vanilla JS** — embedded web UI, no build step, SSE streaming
